# ADR-0001: 废弃上级目录共享模式，改为本地复制与清单声明式分发

- **Status**: Accepted
- **Date**: 2026-11-25

## Context

早期版本采用“本地兄弟目录（`../.agents`）Vendor 内联模式”，要求开发者将本仓库克隆至所有业务项目的父级目录并命名为 `.agents`，业务项目通过相对路径 `../.agents/rules/*.md` 与 `../.agents/skills` 向上跨目录引用规则与技能。

由于现代编码 Agent 的沙箱与安全边界限制，业务项目内的技能与配置已无法通过向上级公共目录寻址的方式加载，原分发架构不可行。同时，将全部外部第三方技能源码内联在规范仓库中导致锁文件漂移、上游同步成本高、与团队自研私有技能混杂。

## Decision

废弃 `../.agents` 上级公共目录引用架构，将团队规范资产划分为三类并分别采用以下分发策略：

1. **静态规则（Rules）**：维护在本仓库中，在目标业务项目初始化或增量更新时直接复制到目标项目中。
2. **第三方技能（External Skills）**：本仓库不再内联第三方技能源码，改为仅维护一份声明式第三方技能清单（定义每个技能安装到 `global` 还是 `project`），由初始化工具调用第三方技能安装方式直接安装。
3. **私有技能（Private Skills）**：维护在本仓库中，在目标业务项目初始化或增量更新时直接拷贝到目标项目的 `.agents` 目录中。
4. **托管与接入方式**：本仓库托管于 GitHub，支持在任意业务项目根目录执行一行命令完成初始化，并兼容已初始化项目、已有 `.agents` 目录及已有规则文件的老项目进行安全增量更新。

## Consequences

### Positive
- 彻底消除跨父目录访问带来的安全沙箱拦截与目录结构强耦合问题，业务项目在任意嵌套路径下均可独立工作。
- 本仓库不再背负大量外部第三方技能源码的 Vendor 维护负担，清晰区分“第三方依赖清单”与“团队自研私有资产”。
- 支持第三方技能按 `global` / `project` 分层安装，减少重复冗余。

### Negative / Trade-offs
- 团队规则或私有技能更新后，业务项目需要重新运行一行增量更新命令来同步最新文件（不再“父目录 `git pull` 自动全局生效”）。
- 初始化安装第三方技能时依赖网络或镜像源可达性（不再完全离线）。
- 初始化工具必须精细处理文件所有权与冲突合并，确保增量更新不破坏业务项目原有定制内容。

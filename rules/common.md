# 通用代码质量规范与安全红线 (Common Standards)

本文件是团队所有项目的通用工程红线准则，所有 Agent 在阅读、编写或重构代码时必须无条件遵守。

---

## 1. 架构与设计原则

- **深度模块设计 (Deep Modules)**：优先设计“对外接口简单小巧、内部实现强大完备”的深度抽象，杜绝浅层包装（Shallow Modules）。
- **职责单一 (SRP)**：每个函数、模块或类仅承担一个明确的职责；单个函数原则上不超过 50 行，逻辑过长必须做合理语义化切分。
- **禁止过度设计 (YAGNI)**：只实现当前需求明确要求的逻辑，不要为虚构的未来场景编写无用的抽象层与钩子。

---

## 2. 编码风格与命名约定

- **命名自解释**：
  - 严禁使用无意义命名（如 `data2`, `temp`, `obj`, `res1`, `foo`）；
  - 变量使用名词，布尔变量使用 `is / has / should / can` 前缀，函数/方法使用动词或动宾短语（如 `fetchUserProfile`, `validatePayload`）；
  - 项目内变量与函数命名风格保持统一（TS/JS 使用 `camelCase`，Python 使用 `snake_case`，Go 根据导出使用 PascalCase / camelCase）。
- **消除魔法值**：所有状态码、超时阈值、固定配置必须定义为常量（Constant）或枚举（Enum），并在顶层集中管理。

---

## 3. 防御性编程与异常处理

- **空值与边界校验**：
  - 对外部输入、网络响应、文件读取结果强制做判空与合法性校验；
  - 善用语言的原生安全访问特性（如可选链 `?.`、空值合并 `??`、Guard Clauses 卫语句）。
- **严禁吞异常**：
  - 严禁写空的 `catch (e) {}` 或直接 `except: pass`；
  - 捕获异常必须有处理逻辑（重试、降级兜底、或打印带完整堆栈上下文的日志并抛出自定义异常）。
- **资源安全释放**：文件句柄、数据库连接、流等资源必须在 `finally` 块、`using` 或 `defer` 语句中确保释放。

---

## 4. 安全规范红线 (Security Hardlines)

> [!CAUTION]
> 以下属于不可逾越的最高安全红线，违规代码将被静态检查或 Code Review 直接阻断：

1. **绝对禁止硬编码秘钥**：
   - 严禁在代码中明文写入 API Key、Access Token、数据库密码、私钥证书；
   - 所有敏感信息必须通过环境变量（`process.env` / `os.environ`）或密钥管理器注入，且在 `.gitignore` 中确保排除 `.env` 等敏感文件。
2. **防注入与数据安全**：
   - SQL 查询强制使用参数化绑定（Parameterized Queries / ORM），严禁字符串拼接 SQL；
   - Web 渲染对用户输入进行严格转义（XSS 防御），命令执行严禁拼接未经校验的用户输入。
3. **敏感日志脱敏**：
   - 严禁将用户密码、身份证、完整手机号、银行卡或完整 JWT 打印到日志中。

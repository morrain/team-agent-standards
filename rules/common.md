# 通用代码质量规范与安全红线 (Common Standards)

本文件是团队所有项目的通用工程质量与安全红线准则，所有 Agent 在阅读、编写或重构代码时必须无条件遵守。

---

## 1. 架构与设计原则

- **深度模块设计 (Deep Modules)**：优先设计“对外接口极简小巧、内部实现强大完备”的深度抽象，坚决杜绝仅作属性透传的浅层包装（Shallow Modules）；
- **职责单一 (SRP) 与行数指标**：
  - 每个函数、模块或类仅承担一个明确的职责；
  - 单个函数原则上不超过 50 行，圈复杂度严格控制在 10 以内；逻辑复杂时必须做合理语义化切分；
- **卫语句与提早返回 (Guard Clauses)**：优先在函数顶部校验前置条件并提前返回（Early Return），代码嵌套层级原则上不得超过 3 层；
- **禁止过度设计 (YAGNI)**：只实现当前需求明确要求的逻辑，严禁为虚构的未来场景编写无真实调用者的抽象层、泛型包装与钩子；
- **严格遵循 DRY 原则 (Don't Repeat Yourself)**：
  - 严禁复制粘贴重复代码；两处及以上相同或高度相似的业务处理逻辑，必须提炼抽象为通用公共函数或组件；
  - **数据契约单一真理来源**：数据结构、接口契约（Type/Interface）与业务常量必须在核心领域模块中统一定义，严禁各业务模块局部随手重复定义类似结构。

---

## 2. 编码风格与命名约定

- **命名自解释**：
  - 严禁使用无意义命名（如 `data2`, `temp`, `obj`, `res1`, `foo`）；
  - 变量使用名词，布尔变量必须使用 `is / has / should / can` 等谓词前缀，函数/方法使用动词或动宾短语（如 `fetchUserProfile`, `validatePayload`）；
  - 项目内变量与函数命名风格保持统一（TS/JS 使用 `camelCase`，Python 使用 `snake_case`，Go 根据导出权限使用 `PascalCase` / `camelCase`）。
- **消除魔法值**：所有状态码、超时阈值、重试次数与业务固定配置必须定义为常量（`const`）或枚举（`enum`），并在顶层或独立配置文件中集中管理。

---

## 3. 防御性编程与异常处理

- **空值与边界校验**：
  - 对外部输入、网络响应、文件读取结果强制做判空与合法性校验；
  - 善用语言的原生安全访问特性（如可选链 `?.`、空值合并 `??`、Pydantic / Zod 数据模型校验）。
- **严禁静默吞异常 (Zero Silent Failures)**：
  - 严禁写空的 `catch (e) {}` 或直接 `except: pass`；
  - 捕获异常必须有处理逻辑（重试、降级兜底、或打印带完整堆栈上下文的日志并抛出包装后的业务异常）。
- **确定性资源释放**：文件句柄、数据库连接、网络流等系统资源必须在 `finally` 块、`using`、`defer` 语句或上下文管理器中确保确定性释放。

---

## 4. 类型安全与可观测性

- **严格类型保障**：
  - TypeScript 中严禁无节制使用 `any`（必须使用 `unknown` 并通过类型守卫收窄类型，或明确定义 `interface` / `type`）；
  - Python 关键业务函数强制标注类型提示（Type Hints）；
- **结构化生产日志**：
  - 严禁在生产代码中残留未经封装的原生 `console.log` / `print`；
  - 统一日志分级标准（DEBUG/INFO/WARN/ERROR），日志必须采用结构化字段输出（必须携带关键追踪上下文，如 `traceId`, `userId`, `error`）。

---

## 5. 异步与并发安全

- **防异步悬空**：JavaScript/TypeScript 中所有返回 Promise 的异步调用必须显式 `await`、返回或捕获错误，严禁未受控的 Floating Promises；
- **生命周期受控**：在 Go 或 Python 中启动后台协程/任务时，必须携带 Context 或超时取消机制，严禁启动无法终止的孤儿协程导致内存泄漏；
- **并发互斥与连接池**：高并发场景下对共享可变状态必须加锁或通过 Channel/队列同步，避免竞态条件；严禁在循环内无节制创建数据库或 HTTP 客户端连接。

---

## 6. 最高安全红线 (Security Hardlines)

> [!CAUTION]
> 以下属于不可逾越的最高安全红线，违规代码将被静态检查或 Code Review 直接阻断：

1. **绝对禁止硬编码秘钥**：
   - 严禁在代码中明文写入 API Key、Access Token、数据库密码、私钥证书；
   - 所有敏感信息必须通过环境变量（`process.env` / `os.environ`）或密钥管理器注入，且在 `.gitignore` 中确保排除 `.env` 等敏感文件。
2. **防注入与数据安全**：
   - SQL 查询强制使用参数化绑定（Parameterized Queries / ORM），严禁字符串拼接 SQL；
   - Web 渲染对用户输入进行严格转义（XSS 防御），命令执行严禁拼接未经校验的用户输入。
3. **敏感日志脱敏**：
   - 严禁将用户明文密码、身份证、完整手机号、银行卡或完整 JWT 打印到日志中。

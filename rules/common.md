# 通用代码质量规范与安全红线 (Common Standards)

> **分级约定**：`[MUST]` 为不可逾越的阻断级红线；`[SHOULD]` 为默认遵循的工程准则（偏离时须说明理由）。

---

## 1. 架构与设计原则

- `[SHOULD]` **深度模块设计 (Deep Modules)**：优先设计“对外接口极简、内部实现完备”的深度抽象，杜绝仅作属性透传的浅层包装（Shallow Modules）；
- `[SHOULD]` **职责单一与拆分信号**：函数/模块职责单一；以逻辑内聚与可读性为先，单函数超过 50 行或圈复杂度超过 10 时作为**重构审视信号**（避免为凑行数机械拆出浅层碎函数）；
- `[SHOULD]` **卫语句与扁平控制流**：优先在函数顶部校验前置条件并提早返回（Early Return），嵌套层级控制在 3 层以内；
- `[SHOULD]` **禁止过度设计 (YAGNI)**：只实现当前需求明确要求的逻辑，不为虚构未来场景编写无调用者的抽象层或钩子；
- `[SHOULD]` **遵循 DRY 与架构一致性**：新增工具方法前先检索复用，杜绝“影子函数”；类型契约与常量在核心领域模块统一定义；严格遵循项目既有分层依赖流向（如表现层 -> 业务层 -> 数据访问层），严禁跨层逆向调用。

---

## 2. 编码风格与命名约定

- `[SHOULD]` **命名自解释**：严禁无意义命名（`data2`, `temp`, `res1`, `foo`）；布尔变量使用 `is/has/should/can` 谓词前缀，函数使用动宾短语；遵循语言惯例（TS/JS `camelCase`，Python `snake_case`，Go `PascalCase`/`camelCase`）；
- `[SHOULD]` **消除魔法值**：状态码、超时阈值、重试次数与固定业务配置集中定义为常量或枚举。

---

## 3. 防御性编程、可靠性与数据一致性

- `[MUST]` **严禁静默吞异常 (Zero Silent Failures)**：严禁空的 `catch (e) {}` 或 `except: pass`；捕获异常必须有明确处理（精准区分可预期错误码、降级兜底、或记录带完整上下文的结构化日志并抛出包装异常）；
- `[MUST]` **确定性资源释放**：文件句柄、数据库连接、网络流必须在 `finally` / `using` / `defer` / 上下文管理器中确保释放；
- `[MUST]` **外部调用显式超时与边界限制**：所有 HTTP、RPC、数据库及子进程调用必须配置显式超时（Timeout）；批量查询强制分页或 `LIMIT`；大文件与未知体积 IO 优先流式处理（Stream / Iterator），严禁无上限一次性读入内存；对外部输入请求体、批量数组长度与上传文件大小施加显式上限；
- `[MUST]` **事务边界与幂等性**：涉及多步关联持久化写入时必须明确事务边界，防止部分写入脏数据；对外写接口与异步消费任务须考虑重试幂等性；
- `[SHOULD]` **空值与契约校验**：对外部输入、网络响应与文件读取结果做判空与 Schema 校验（如 Zod / Pydantic / 可选链 `?.`）。

---

## 4. 类型安全与可观测性

- `[SHOULD]` **严格类型保障**：TypeScript 严禁无节制使用 `any`（优先 `unknown` + 类型守卫或明确定义接口）；Python 关键业务函数标注 Type Hints；
- `[SHOULD]` **结构化生产日志**：服务端与 Web 应用严禁残留未经封装的 `console.log` / `print`，统一分级（DEBUG/INFO/WARN/ERROR）并携带关键追踪上下文（`traceId`, `userId`, `error`）；*CLI 工具面向用户的标准输出（stdout/stderr）除外*。

---

## 5. 异步与并发安全

- `[MUST]` **防异步悬空与孤儿任务**：JS/TS 中所有 Promise 必须显式 `await`、返回或捕获错误；Go/Python 后台协程或任务必须携带 Context 或超时取消机制；
- `[MUST]` **并发互斥与连接复用**：共享可变状态必须加锁或通过队列/Channel 同步；严禁在循环内无节制创建数据库或 HTTP 客户端连接。

---

## 6. 最高安全红线 (Security Hardlines)

> [!CAUTION]
> 以下均为 `[MUST]` 阻断级安全红线，违规代码将被静态检查或 Code Review 直接阻断：

1. **严禁硬编码秘钥**：严禁明文写入 API Key、Access Token、数据库密码或私钥；必须通过环境变量或密钥管理器注入，并在 `.gitignore` 排除 `.env`；
2. **防注入与路径/SSRF 安全**：
   - SQL 查询强制参数化绑定（Parameterized Queries / ORM），严禁字符串拼接；
   - Web 渲染严格防 XSS 转义；命令执行严禁拼接未经校验的外部输入（优先关闭 Shell 并做白名单校验）；
   - 用户可控文件路径必须规范化并校验不逃逸根边界（防 Path Traversal）；外部 URL 请求须校验协议与目标白名单（防 SSRF）；
3. **服务端鉴权与越权防御 (AuthN/AuthZ)**：所有写操作与敏感读操作必须在服务端校验当前用户身份与目标资源归属权限（防 IDOR 越权）；
4. **敏感日志脱敏**：严禁将明文密码、身份证、完整手机号、银行卡或完整 JWT 写入日志或暴露给客户端。

---

## 7. 依赖引入纪律与包管理器一致性 (Dependency Discipline)

- `[MUST]` **包管理器唯一**：严格遵循既有 Lockfile（pnpm/yarn/npm, poetry/uv, go.mod, cargo），严禁混用生成多份冲突 lockfile；
- `[MUST]` **防依赖幻觉与引入审批**：严禁编造不存在的三方包名；新增生产依赖前必须向开发者说明包名、理由与成熟度并获得确认；
- `[SHOULD]` **标准库优先**：优先使用语言标准库与运行时原生能力，避免为简单工具引入重型三方库。

---

## 8. 用户可见文案与错误提示规范 (User-Facing Copy & Error Messages)

适用于所有终端用户可见文本，包括**前端界面文案（标题、按钮、表头、占位符、设置项）、后端返回给用户的错误提示，以及 CLI 交互提示**：

- `[SHOULD]` **禁止不必要的括号备注**：严禁出现多余的括号解释或中英夹杂备注（如“通用设置（系统默认）”、“账号 ID（如 demo_user）”、“账户余额（元）”在已有 `¥` 符号时）；
- `[SHOULD]` **言简意赅、准确真实**：用词克制直接，准确反映当前功能状态或可执行的纠错指引，严禁将内部架构隐喻、表名/堆栈、开发阶段说明或给开发者的备注泄露到用户文案与错误提示中。
